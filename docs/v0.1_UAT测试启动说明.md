# v0.1 UAT 测试启动说明

版本：v0.1 / PRD v1.3 口径
测试地址：`http://101.201.69.137`
适用对象：测试主持人、商家测试员、业务员测试员、审核员测试员、出纳测试员、超级管理员
测试目标：让不同角色按真实协作方式完成一次业务测试，验证商家入驻、商家凭证查看、业务员验机、审核处理、出纳打款、后台管理是否可用。

## 1. 测试前说明

### 1.1 测试范围

本次测试只验证 v0.1 范围内的测试版功能：

- 商家入驻申请、入驻状态查看。
- 商家查看本商家的打款凭证列表和凭证详情。
- 业务员查看任务、验机、提交验机、补充资料。
- 审核员指派业务员、审核通过、审核驳回、要求业务员补资料。
- 出纳查看待打款记录、上传凭证、预览凭证、确认打款。
- 超级管理员重置测试数据、查看账号、商家管理、凭证管理、状态调整。

本次测试不验证真实短信、真实银行、真实支付、真实合同、账单、逾期、锁机或解锁能力。

## 4. 角色测试路径

### 4.1 商家测试路径

商家只测试商家自己的入驻和凭证，不测试客户申请处理。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 使用 `store001 / 123456` 登录 | 进入商家端 |
| 2 | 查看入驻页 | 显示商家入驻状态和商家资料 |
| 3 | 查看凭证页 | 只显示本商家的打款凭证 |
| 4 | 点击任意凭证 | 进入凭证详情 |
| 5 | 点击凭证预览 | 可查看图片或 PDF |
| 6 | 查看我的页面 | 显示商家基础信息和收款信息脱敏结果 |
| 7 | 使用 `store002` 重复查看 | 只能看到 `store002` 的数据 |

重点判断：

- 商家不能看到客户完整申请资料。
- 商家不能看到合同、账单、逾期、锁机、解锁。
- 商家不能处理客户补资料。
- 商家不能看到其他商家的凭证。

### 4.2 业务员测试路径

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 使用 `sales001 / 123456` 登录 | 进入业务员端 |
| 2 | 查看任务列表 | 看到分配给自己的任务 |
| 3 | 点击任务卡片 | 详情紧接卡片展示或进入移动端详情页 |
| 4 | 开始验机 | 状态进入验机中 |
| 5 | 填写验机备注并提交 | 状态进入待审核 |
| 6 | 若审核员要求补资料 | 业务员看到需补资料任务 |
| 7 | 补充资料后重新提交 | 申请回到待审核 |

重点判断：

- 手机端点击卡片后，用户能立刻看到详情。
- 业务员只看到自己的任务。
- 补资料入口只出现在业务员端，不出现在商家端。

### 4.3 审核员测试路径

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 使用 `audit001 / 123456` 登录 | 进入审核员工作台 |
| 2 | 选择待派单申请 | 可选择业务员 |
| 3 | 指派业务员 | 申请进入已指派 |
| 4 | 等业务员提交验机 | 申请进入待审核 |
| 5 | 审核通过 | 申请进入待打款 |
| 6 | 审核驳回 | 申请进入已驳回，不进入出纳待打款 |
| 7 | 要求补资料 | 处理对象只能是业务员 |

重点判断：

- 审核员不能把客户申请补资料指向商家。
- 审核通过后出纳端必须出现待打款记录。
- 驳回后出纳端不应出现待打款记录。

### 4.4 出纳测试路径

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 使用 `cashier001 / 123456` 登录 | 进入出纳工作台 |
| 2 | 选择待打款记录 | 右侧或详情区出现确认打款表单 |
| 3 | 输入等于或小于贷款金额的打款金额 | 可继续上传凭证 |
| 4 | 输入大于贷款金额的金额 | 系统阻止确认 |
| 5 | 上传图片凭证 | 出现文件信息和预览入口 |
| 6 | 上传 PDF 凭证 | 可预览 PDF |
| 7 | 点击确认打款 | 状态变为已打款，商家端出现对应凭证 |

重点判断：

- 打款金额不能超过客户申请分期付款金额。
- 未上传凭证不能确认打款。
- 凭证上传后必须可预览。
- 出纳确认打款后，商家能看到凭证。

### 4.5 超级管理员测试路径

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 使用 `admin001 / 123456` 登录 | 进入超级管理员页面 |
| 2 | 查看账号列表 | 能看到全部测试账号 |
| 3 | 查看商家管理 | 能看到商家入驻申请 |
| 4 | 审核通过商家入驻 | 商家端显示已通过 |
| 5 | 驳回商家入驻 | 商家端显示驳回原因 |
| 6 | 新增打款凭证 | 对应商家端可以看到凭证 |
| 7 | 作废打款凭证 | 商家端显示作废状态 |
| 8 | 重置测试数据 | 所有测试数据恢复初始状态 |

重点判断：

- 非超管不能进入商家管理和凭证管理。
- 超管可以恢复异常数据，方便下一轮测试。

## 5. 推荐测试顺序

### 5.1 第一轮：快速冒烟

| 顺序 | 角色 | 操作 |
|---|---|---|
| 1 | 商家 | 登录并查看入驻、凭证、我的 |
| 2 | 业务员 | 登录并查看任务 |
| 3 | 审核员 | 登录并查看派单和审核区 |
| 4 | 出纳 | 登录并查看待打款记录 |
| 5 | 超管 | 登录并查看商家管理和凭证管理 |

### 5.2 第二轮：正向闭环

| 顺序 | 角色 | 操作 |
|---|---|---|
| 1 | 审核员 | 指派业务员 |
| 2 | 业务员 | 提交验机 |
| 3 | 审核员 | 审核通过 |
| 4 | 出纳 | 上传凭证并确认打款 |
| 5 | 商家 | 查看对应打款凭证 |

### 5.3 第三轮：异常分支

| 分支 | 测试目标 |
|---|---|
| 审核驳回 | 验证驳回后不会进入打款 |
| 业务员补资料 | 验证补资料流转给业务员 |
| 超额打款 | 验证出纳不能确认超过贷款金额的打款 |
| 未上传凭证 | 验证出纳不能空凭证确认打款 |
| 商家隔离 | 验证商家不能看到其他商家凭证 |
| 非法权限 | 验证非超管不能进入后台商家管理 |

## 6. 问题记录模板

| 字段 | 填写说明 |
|---|---|
| 问题编号 | 例如 `BUG-001` |
| 发现角色 | 商家/业务员/审核员/出纳/超管 |
| 测试设备 | 手机型号或电脑浏览器 |
| 页面位置 | 例如商家凭证详情、出纳确认打款 |
| 操作步骤 | 写清楚从登录开始的复现步骤 |
| 预期结果 | 按业务应该发生什么 |
| 实际结果 | 实际看到什么 |
| 截图或录屏 | 文件名或链接 |
| 问题等级 | 高/中/低 |
| 是否阻塞测试 | 是/否 |
| 备注 | 其他说明 |

问题等级建议：

| 等级 | 定义 |
|---|---|
| 高 | 主流程无法继续、权限泄露、金额错误、数据错乱 |
| 中 | 某个分支无法完成、提示不清楚、页面明显遮挡 |
| 低 | 文案、间距、颜色、非阻塞体验问题 |

## 7. 已知限制

- 当前为业务测试版，不连接真实短信、银行、支付接口。
- 当前凭证文件以测试文件和测试元数据为主。
- 测试数据可以被超级管理员重置，测试过程中不要录入真实客户隐私信息。
- 生产 Docker 容器不内置 PHPUnit 自动化测试工具，后端自动化测试需在开发环境或专用测试镜像执行。
- 手机端以 H5 方式测试，后续仍可继续做更细的高保真体验优化。

## 8. 测试结束复盘清单

| 复盘项 | 记录内容 |
|---|---|
| 主流程是否跑通 | 是否完成从验机到打款凭证查看 |
| 商家权限是否正确 | 是否只看到入驻和凭证 |
| 异常分支是否跑通 | 驳回、补资料、超额打款、未上传凭证 |
| 哪些页面不好理解 | 记录角色和页面 |
| 哪些字段缺失 | 记录字段名称和使用场景 |
| 哪些权限还要收紧 | 记录角色、入口、风险 |
| 下一版优先级 | 按高/中/低列出建议 |

## 9. 测试主持人收尾动作

1. 汇总所有问题记录和截图。
2. 标记阻塞问题和非阻塞问题。
3. 确认是否需要再次重置测试数据复测。
4. 输出一份测试结论：通过、带问题通过、未通过。
5. 整理下一版优先修复清单。
