# v1.3 H5 竞品风格 UI 改造设计说明

日期：2026-06-08
范围：P2BOYUAN 手机 H5 角色体验改造
状态：已根据用户确认的方案 B 编写

## 1. 背景

当前 v0.1 已完成部署、数据库迁移、核心接口冒烟检查和页面人工验证。下一阶段目标是把手机端角色体验改造成更接近竞品的 H5 App 风格。

用户确认的方向：

- 凡是手机 H5 使用场景，统一改成竞品“订单中心 / 录单台”式布局。
- 布局基本参考竞品：顶部标题、白色概览卡、横向状态 Tab、订单/任务卡片列表、纵向详情页、底部 Tab。
- 审核流程也要按角色权限改造，让不同角色看到自己该处理的审核节点。
- 每个订单或任务卡片加入 iPhone 机型图片。
- 视觉色系使用淡蓝、白卡、深蓝字、橙色当前 Tab 标识。
- 字体不使用楷体、仿宋或手写感字体，统一使用类似微软雅黑的无衬线字体。

## 2. 总体方案

采用“移动 H5 统一重构 + 后台轻优化”的方案。

移动 H5 角色：

- 商家
- 业务员
- 出纳

这些角色使用统一的 H5 视觉语言和交互框架：

- 顶部页面标题
- 角色中心概览卡
- 数据统计卡
- 横向状态筛选
- 卡片式订单/任务列表
- 点击卡片进入纵向详情页
- 详情页底部固定主操作
- 底部 Tab 导航

电脑后台角色：

- 审核员
- 超级管理员

这些角色保留电脑后台风格，只做视觉统一、布局整理和信息密度优化，不强行改成手机 H5。

## 3. 视觉规范

### 3.1 字体

统一使用无衬线字体栈：

```css
font-family: "Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", Arial, sans-serif;
```

规则：

- 不使用楷体、仿宋、宋体或手写风格字体。
- 中文标题可以加粗，但不做书法感。
- 编号、金额、状态必须清晰易读。
- 字体大小不随视口宽度缩放，避免移动端抖动和错位。

### 3.2 色彩

主视觉参考竞品淡蓝风格：

- 页面背景：浅蓝 `#eaf1ff`、`#f7faff`
- 主文字：深蓝 `#172b5f`
- 次级文字：灰蓝 `#6172a5`
- 卡片背景：白色 `#ffffff`
- 信息块背景：浅蓝 `#f1f5ff`
- 当前 Tab 标识：橙色 `#ff805c`
- 主按钮：蓝色 `#3f5fd0`

绿色不作为主视觉色，只在成功状态或极少数状态标签中使用。

### 3.3 卡片和布局

- 手机页面宽度按真实 H5 竖屏优先设计。
- 页面主体使用浅蓝背景。
- 主要内容使用白色大圆角卡片。
- 概览卡包含英文小标题、中文主标题、语言/状态胶囊、统计块。
- 列表卡片展示编号、状态、iPhone 图片、机型、关键参数、金额。
- 底部 Tab 固定在底部，三个入口为主。

## 4. 页面结构

### 4.1 商家 H5

底部 Tab：

- 入驻
- 凭证
- 我的

页面结构：

- 顶部：我的商家
- 概览卡：商家中心、入驻状态、凭证总数
- 状态 Tab：全部、待确认、已打款、已作废
- 凭证卡片：凭证编号、状态、iPhone 图片、关联业务编号、商家名称、打款金额
- 凭证详情：凭证编号、金额、状态、打款时间、脱敏收款账号、凭证文件预览、备注、作废原因
- 我的：商家编号、商家名称、联系人、联系方式、入驻状态、收款信息脱敏展示

权限规则：

- 商家只能看到本商家的入驻资料和打款凭证。
- 商家不能看到客户完整申请资料。
- 商家不能看到合同、账单、逾期、锁机或解锁。
- 商家不能处理客户补资料、审核或打款。

商家可见审核流程：

```text
未提交入驻
→ 待审核
→ 已通过 / 已驳回
→ 已通过后可查看凭证
```

### 4.2 业务员 H5

底部 Tab：

- 任务
- 录单台
- 我的

页面一：任务中心

- 顶部：我的任务
- 概览卡：任务中心、任务总数、进行中任务
- 状态 Tab：全部、待验机、验机中、需补资料、待审核、已驳回、已打款
- 任务卡片：申请编号、状态、iPhone 图片、客户摘要、机型、颜色、容量、贷款金额
- 点击卡片进入任务详情

页面二：录单台

布局参考用户提供的竞品录单台：

- 顶部：录单台
- 说明卡：业务员协助录单说明
- 基础业务信息：业务员编号、商家选择、手机型号
- 方案配置：商品信息、还款周期、分期数、贷款金额、订单备注
- 客户基础信息：姓名、电话、证件类型、证件号码、居住地址、工作信息
- 紧急联系人：关系、姓名、电话
- 资料上传区：证件、工作证明、付款凭证、补充资料
- 底部操作：保存草稿、提交审核

业务员可见审核流程：

```text
录单草稿
→ 提交审核
→ 待审核
→ 审核通过后进入待打款
→ 审核驳回时业务员看到已驳回原因
→ 要求补资料时业务员回到录单台补齐资料
```

权限规则：

- 业务员可以处理分配给自己的任务。
- 业务员可以录入/补充客户申报资料。
- 业务员不能审核通过。
- 业务员不能打款。
- 业务员不能查看其他业务员任务。

### 4.3 出纳 H5

底部 Tab：

- 打款
- 凭证
- 我的

页面结构：

- 顶部：我的打款
- 概览卡：打款中心、待打款数量、已打款金额
- 状态 Tab：全部、待打款、已打款、凭证异常
- 打款卡片：申请编号、状态、iPhone 图片、商家、机型、最高可打款金额、凭证状态
- 打款详情：申请摘要、商家信息、贷款金额、实际打款金额、上传凭证、凭证预览、确认打款

出纳可见审核流程：

```text
待打款
→ 上传凭证
→ 预览确认
→ 确认打款
→ 已打款
→ 商家可见凭证
```

规则：

- 实际打款金额不能超过申请分期付款金额。
- 未上传凭证不能确认打款。
- 凭证支持图片和 PDF 预览。
- 确认打款后生成商家可见凭证。

### 4.4 审核员后台

审核员保留电脑后台风格。

优化点：

- 列表、详情、操作区不再互相遮挡。
- 状态标签和 H5 端状态保持一致。
- 补资料对象只允许业务员。
- 详情抽屉展示客户资料、设备资料、验机资料和审核动作。

审核员处理流程：

```text
待派单
→ 指派业务员
→ 待业务员验机
→ 待审核
→ 审核通过 / 审核驳回 / 要求业务员补资料
```

### 4.5 超级管理员后台

超级管理员保留电脑后台风格。

优化点：

- 商家管理独立成区。
- 打款凭证管理独立成区。
- 账号、状态调整、重置数据保持可用。
- 状态和权限说明更清楚。

超管可见审核流程：

```text
商家入驻待审核
→ 审核通过 / 驳回
→ 商家端展示结果

打款凭证管理
→ 新增凭证 / 作废凭证
→ 商家端展示凭证状态
```

## 5. iPhone 图片策略

v0.1 UI 改造先使用内置静态图片资源，覆盖常见机型：

- iPhone 17 Pro Max
- iPhone 16 Pro Max
- iPhone 16 Pro
- iPhone 15 Pro
- iPhone 14 Pro

实现规则：

- 卡片必须有机型图片，不再使用空白占位。
- 如果申请记录没有图片，按机型名称匹配默认图片。
- 如果后续接商品库，优先显示商品库图片。
- 图片应保持清晰、浅背景、可识别机型，不使用暗色氛围图。

## 6. 分阶段实施

### 第一阶段：业务员 H5

优先改业务员，因为用户已经明确要求“仿照竞品录单台布局和流程做业务员界面”。

范围：

- 任务中心改成订单中心式布局。
- 新增或重构录单台页面。
- 底部 Tab 改为任务 / 录单台 / 我的。
- 卡片加入 iPhone 图片。
- 详情页改成纵向详情，底部固定操作。

不在第一阶段做：

- 真实商品库。
- 真实文件上传重构。
- 复杂合同签署。

### 第二阶段：出纳 H5

范围：

- 打款中心改成订单中心式布局。
- 打款卡片加入 iPhone 图片。
- 详情页强化金额限制、上传、预览、确认。
- 底部 Tab 改为打款 / 凭证 / 我的。

### 第三阶段：商家 H5

范围：

- 商家中心改成同一视觉风格。
- 凭证卡片加入 iPhone 图片。
- 入驻页和我的页面使用淡蓝白卡风格。

### 第四阶段：审核员与超管后台

范围：

- 视觉统一。
- 列表和详情布局整理。
- 商家入驻审核、申请审核、凭证管理状态对齐。

## 7. 验收标准

移动 H5：

- 手机端没有横向滚动。
- 所有主要列表使用统一卡片布局。
- 所有订单/任务卡片都有 iPhone 图片。
- 点击卡片后能进入清楚的纵向详情页。
- 当前角色只能看到自己权限内的审核流程和操作按钮。
- 字体统一为无衬线，不出现楷体或手写风格。
- 主色为淡蓝和白色，当前 Tab 使用橙色短下划线。

业务员第一阶段：

- 业务员能从任务中心进入任务详情。
- 业务员能从录单台保存草稿和提交审核。
- 业务员能在需补资料状态回到录单台补齐资料。
- 审核员看到业务员提交后的待审核状态。

权限：

- 商家不出现客户完整申请处理入口。
- 出纳不出现审核入口。
- 业务员不出现打款入口。
- 审核员补资料对象不出现商家。
