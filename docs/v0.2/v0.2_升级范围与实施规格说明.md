# v0.2 升级范围与实施规格说明

版本：v0.2  
版本名称：内部试运行版  
日期：2026-06-08  
适用项目：手机分期回收平台

## 1. 文档目的

本文件用于把当前演示系统升级到 v0.2 内部试运行版之前的开发范围固定下来。v0.2 的目标不是增加新的商业模式，而是让系统具备小范围真实或脱敏业务试运行能力。

v0.2 必须重点解决五类问题：

1. 正式账号管理能力不足。
2. 权限边界需要更严格验证。
3. 附件上传、预览、下载需要成为稳定能力。
4. 操作日志需要可追溯。
5. 列表查询需要支持内部运营筛选。

## 2. 当前基础

当前系统已经具备以下能力：

- Vue H5 + PHP Laravel API + MySQL + Docker 部署。
- 店家、业务员、审核员、出纳、超级管理员五类角色登录。
- 申请单、派单、验机、审核、补资料、打款、凭证查看主流程。
- 商家入驻申请、商家资料、商家打款凭证列表和详情。
- H5 端已改造成更接近竞品的订单中心、录单台、打款中心、商家中心风格。
- 已有基础附件上传、图片/PDF 预览和出纳凭证上传。
- 已有部分状态日志、UAT 文档、完整 API 文档和数据表说明。

## 3. v0.2 总体定位

v0.2 是“内部试运行版”，服务对象是内部小范围测试人员和少量真实或脱敏业务数据。

核心原则：

- 可以试运行，但不直接承诺生产级 SLA。
- 可以录入真实或脱敏业务，但必须限制隐私暴露范围。
- 不做 C 端商城、不做账单还款、不接真实短信、银行、支付或锁机 API。
- 后续 v0.3 及之后的业务扩展，需要建立在 v0.2 的账号、权限、附件、日志基础上。

## 4. 本期做什么

### 4.1 账号管理

超级管理员新增账号管理能力：

- 查看账号列表。
- 创建账号。
- 停用账号。
- 重置密码。
- 分配角色。
- 店家账号绑定门店。
- 业务员账号绑定业务员档案。
- 记录最后登录时间。
- 记录密码更新时间。

默认角色范围保持五类：

- `STORE`
- `SALES`
- `AUDITOR`
- `CASHIER`
- `SUPER_ADMIN`

验收口径：

- 超管可以创建一个新业务员账号，并用该账号登录。
- 超管可以停用一个账号，停用后该账号不能登录。
- 超管可以重置密码，旧密码失效，新密码可登录。
- 店家账号必须绑定门店，否则不能进入商家端核心页面。
- 业务员账号必须绑定业务员档案，否则不能接收验机任务。

### 4.2 权限加固

v0.2 对权限的要求高于上一阶段演示版。

权限边界：

- 店家只能访问本商家的入驻资料和打款凭证。
- 店家不能访问客户完整申请单、合同、账单、逾期、锁机、解锁信息。
- 业务员只能查看分配给自己的申请和验机任务。
- 审核员可以查看审核池、派单、审核通过、驳回、要求补资料。
- 出纳只能查看待打款/已打款记录，并确认打款。
- 超级管理员可以查看和调整全部演示数据。

验收口径：

- 店家调用申请单列表接口时返回无权限。
- 业务员不能查看未分配给自己的申请详情。
- 出纳不能执行审核通过或驳回。
- 审核员不能确认打款。
- 普通角色不能调用超管接口。

### 4.3 附件中心

当前附件能力存在于流程里，v0.2 需要形成统一的附件管理入口。

新增“文件中心”能力：

- 按申请单查看附件。
- 按模块分类：申请资料、验机资料、补充资料、打款凭证、商家凭证、其他。
- 支持图片预览。
- 支持 PDF 预览或下载。
- 支持下载附件。
- 展示上传人、上传角色、上传时间、文件大小、文件类型。

验收口径：

- 业务员上传验机图片后，申请详情和文件中心都能看到。
- 出纳上传打款凭证后，出纳可预览，店家可在凭证详情中查看。
- PDF 文件可打开预览或下载。
- 文件超过大小限制时给出明确错误。

### 4.4 操作日志

v0.2 要求关键业务动作均可追溯。

日志字段至少包括：

- 关联业务 ID。
- 操作动作。
- 操作者 ID。
- 操作者名称。
- 操作者角色。
- 操作前状态。
- 操作后状态。
- 操作备注。
- 操作时间。

必须记录日志的动作：

- 创建申请。
- 指派业务员。
- 开始验机。
- 提交验机。
- 审核通过。
- 审核驳回。
- 要求补资料。
- 提交补资料。
- 确认打款。
- 商家入驻提交。
- 商家入驻审核通过。
- 商家入驻驳回。
- 商家凭证新增。
- 商家凭证作废。
- 超管手动调整申请状态。

验收口径：

- 每次状态变化都能在申请详情里看到日志。
- 日志记录 before/after 状态。
- 日志不能通过普通业务接口删除。
- 手动调整状态也必须写日志。

### 4.5 列表筛选

v0.2 需要让内部人员能用列表定位数据。

申请列表筛选：

- 状态。
- 店家。
- 业务员。
- 时间范围。
- 关键词。
- 分页。

出纳打款列表筛选：

- 状态。
- 时间范围。
- 关键词。
- 店家。

商家入驻列表筛选：

- 状态。
- 店家/商家名称关键词。
- 时间范围。

商家凭证列表筛选：

- 状态。
- 店家。
- 时间范围。
- 业务编号关键词。

验收口径：

- 每个筛选条件都能单独生效。
- 多条件组合筛选结果准确。
- 清空筛选后回到默认列表。
- 移动端列表不因为筛选栏过长而挤压卡片内容。

### 4.6 申请编号规则

v0.2 需要固化编号生成规则。

建议规则：

```text
A + yyyyMMdd + 4位日流水
```

示例：

```text
A202606080001
```

要求：

- 同一天流水递增。
- 不能重复。
- 超管创建和业务员/店家流程创建都使用同一规则。
- 旧演示数据可保留原编号，但新增数据必须使用新规则。

### 4.7 测试数据与隐私规则

v0.2 开始允许少量真实或脱敏数据试运行，因此需要明确规则。

建议规则：

- 测试人员优先使用脱敏姓名、脱敏手机号、测试证件号。
- 上传真实身份证、银行卡、合同前必须确认测试范围。
- 演示环境不保存生产级敏感资料。
- 超管重置数据会清空当前测试数据，执行前必须确认。
- 对外展示时使用演示数据，不展示真实客户资料。

## 5. 本期不做什么

v0.2 不做以下内容：

- C 端用户自助注册。
- C 端商城。
- 正式商品库存管理。
- 账单还款。
- 真实短信接口。
- 真实支付接口。
- 真实银行打款接口。
- 锁机/解锁接口。
- 风控评分模型。
- 多租户 SaaS 化。

## 6. 页面影响

### 6.1 超级管理员后台

需要新增或增强：

- 账号管理页。
- 文件中心页。
- 日志查看能力。
- 商家管理筛选。
- 商家凭证筛选。

### 6.2 审核员后台

需要增强：

- 申请列表筛选。
- 审核记录展示。
- 附件预览入口。
- 状态日志入口。

### 6.3 出纳端

需要增强：

- 打款列表筛选。
- 凭证预览/下载。
- 打款金额不能超过申请贷款金额。
- 打款后日志可追溯。

### 6.4 业务员 H5

需要增强：

- 只显示自己负责的订单。
- 录单台字段校验。
- 附件上传状态。
- 订单详情中显示补资料和验机附件。

### 6.5 店家 H5

保持最新商家权限口径：

- 商家入驻申请。
- 我的商家信息。
- 打款凭证列表。
- 打款凭证详情。

店家不参与客户完整申请审核链路。

## 7. API 影响

需要新增或增强的 API：

- 账号创建。
- 账号停用。
- 账号重置密码。
- 账号角色/绑定关系更新。
- 附件列表。
- 附件详情。
- 附件下载/预览地址。
- 日志列表增强。
- 申请列表筛选参数增强。
- 出纳列表筛选参数增强。
- 商家入驻列表筛选参数增强。
- 商家凭证列表筛选参数增强。

已有 API 需要同步更新文档，不允许代码改了但文档不改。

## 8. 数据表影响

预计需要新增或调整：

- `users` 增加密码更新时间、停用原因等字段。
- `attachments` 增强上传人、上传角色、业务模块、文件大小、文件类型。
- `status_logs` 确认 before/after 状态、操作人角色、备注字段完整。
- 如当前字段已存在，则只补测试与接口，不重复建表。

实施前需要先以 migration 文件为准复核当前结构，避免重复字段。

## 9. 测试要求

v0.2 必须覆盖以下测试：

- 登录成功/失败。
- 停用账号不能登录。
- 重置密码后旧密码失效。
- 店家越权访问申请接口被拒绝。
- 业务员越权访问其他业务员任务被拒绝。
- 审核员不能确认打款。
- 出纳不能审核。
- 附件上传成功。
- 附件预览/下载成功。
- 超大附件上传失败。
- 申请状态变化写入日志。
- 商家入驻审核写入日志。
- 商家凭证新增/作废写入日志。
- 列表单条件筛选。
- 列表组合条件筛选。
- 申请编号按日期流水生成且不重复。

## 10. 推荐实施顺序

推荐按以下顺序推进：

1. 数据表复核与迁移。
2. 账号管理后端接口与测试。
3. 权限加固测试与修复。
4. 附件中心后端接口与测试。
5. 日志服务补强与测试。
6. 列表筛选接口与测试。
7. 前端后台页面增强。
8. H5 页面小幅补强。
9. API 文档、数据表文档、UAT 文档同步。
10. 本地验证、Docker 构建、服务器部署。

## 11. 默认产品决策

为减少来回确认，v0.2 默认采用以下决策：

- 账号管理只由超级管理员操作。
- 密码重置由超管设置临时密码，不做短信找回。
- 附件存储继续使用当前本地存储方案，不接对象存储。
- 文件下载需要登录鉴权，不开放公开下载链接。
- 日志只追加，不做删除。
- 列表筛选优先支持后端筛选，前端不只做本地过滤。
- 真实短信、银行、支付接口继续保留为后续版本。
